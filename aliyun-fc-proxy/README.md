# 阿里云函数计算 (FC) AI 代理部署说明

解决两个核心问题：
1. 浏览器跨域 (CORS) —— 本地直接调 bayesdl 会被浏览器拦截。
2. 国内手机流量无法访问 `*.workers.dev` —— FC 默认域名 `*.fcapp.run` / `*.fc.aliyuncs.com` 国内可达，且函数计算按需运行、常驻触发器，电脑下线也能用。

---

## 一、前提

- 阿里云账号（https://www.aliyun.com），并完成**实名认证**（函数计算强制要求）。
- 本方案走**按量付费 + 免费额度**：个人低频使用基本为 0 元。免费额度含每月 100 万次函数调用、一定量的执行时长与少量公网出流量。AI 文本响应流量很小，正常用不到收费线。

## 二、控制台创建事件函数（严格按官方步骤）

> 入口**不是**"内置运行时"。正确路径：先选「函数类型 = 事件函数」。FC 3.0 控制台右上角可切换 2.0/3.0，确认停在 **3.0**。

1. 打开函数计算 3.0 控制台：https://fc.console.aliyun.com
2. 左侧「**函数管理**」→「**函数列表**」。
3. 顶部菜单栏**选择地区**（国内：华东1（杭州）/ 华北2（北京）），保证国内访问快。
4. 单击「**创建函数**」。
5. 在弹出的对话框里**选择函数类型 = 事件函数**，单击「**创建事件函数**」。
6. 进入"创建事件函数"页面，按下表逐项填：

   **基础配置**
   - 函数名称：`ai-proxy`
   - 规格方案：`vCPU 0.35 / 内存 512 MB / 磁盘 10 GB`（默认即可；磁盘不计费，无需动）

   **弹性策略（弹性配置）** —— 直接决定费用与冷启动
   - 实例类型：**弹性实例**（按请求量自动伸缩，无请求不收费；不要选性能实例 / GPU 实例）
   - 最小实例数：**0**（关键！保持 0 才不花闲置费；设为 ≥1 会常驻计费。个人低频用 0 即可，首次调用有几百 ms 冷启动，可接受）
   - 单实例并发度：**1**（默认；AI 代理单次上游约 60s，保持 1 最稳，避免慢请求互相挤占）
   - 最大实例数：默认 100，个人用可改小为 **1~2** 控制并发与成本
   - （可选）闲置模式：弹性实例支持；最小实例数=0 时空闲本就不计费，可不开

   **函数代码**
   - 运行环境：**Node.js** → 选 **18 或 20**
   - 代码上传方式：选「**通过 ZIP 包上传**」，上传 `ai-proxy-code.zip`（已为你生成好，就在本目录下；ZIP 里只有一个文件 `index.js`，无子目录、无 package.json）
   - 函数入口（Handler）：`index.handler`（即 index.js 的 exports.handler，无需改）

7. **触发器**：本页若有「触发器」区，添加 **HTTP 触发器**，认证方式选「**无需认证**」；若本页无触发器选项，创建后在「函数详情 → 触发器」页签创建 HTTP 触发器（同样 无需认证）。
8. 单击「**创建**」。

## 三、（可选但推荐）配置环境变量，避免 key 下发到浏览器

在函数配置 → 环境变量 中新增：

| 键 | 值 |
| --- | --- |
| `UPSTREAM_ENDPOINT` | `https://token.bayesdl.com/api/maas/v1/chat/completions` |
| `UPSTREAM_API_KEY` | `sk-022726afe4ff4bb8a4b2e499d9e51fe2` |
| `UPSTREAM_MODEL` | `glm-5.1` |

配置后，客户端只需发 `{ model, messages }`，key 由服务端注入，更安全。
不配置也行——函数会照常读取 App 传来的 `{ endpoint, apiKey, model, messages }`。

## 四、获取触发 URL

函数创建后，在「触发器」里能看到 HTTP 触发器的公网地址，形如：

```
https://<随机前缀>.cn-hangzhou.fcapp.run
```

或旧格式：

```
https://<账号ID>.<region>.fc.aliyuncs.com/<版本>/proxy/<服务>/<函数>
```

**这就是你的代理地址（HTTPS，国内可达，始终在线）。**

## 五、在 App 里填写

打开 App 设置，把「代理地址 / Proxy URL」填成上面那个 FC 触发器 URL。其余不变：

- 接口地址：`https://token.bayesdl.com/api/maas/v1/chat/completions`
- Key：`sk-022726afe4ff4bb8a4b2e499d9e51fe2`
- Model：`glm-5.1`

> 若第三步配置了环境变量，App 里 `callAIViaProxy` 仍可照常发完整字段（函数会忽略服务端已有的 key，以服务端为准）；或改造为只发 `{model, messages}`。

## 六、自测

1. 浏览器直接打开触发 URL：应返回 404/空（GET 未实现），说明地址可达、域名没被墙。
2. 用 App 发一条消息，应正常拿到 AI 回复。
3. 手机切到流量（4G/5G）再测一次，确认能通——这正是本方案要解决的。

## 七、排查

- App 报 `Failed to fetch`：确认触发 URL 是 `https://` 开头；确认触发器认证=无需认证。
- 返回 `缺少 endpoint 或 apiKey`：App 未传且未配置环境变量，二选一补上。
- 返回 `代理请求上游失败`：检查 `UPSTREAM_ENDPOINT` 是否带 `/chat/completions`，以及 key 是否正确。
- 函数计算偶发冷启动（几十毫秒~1秒），首次调用稍慢属正常。
