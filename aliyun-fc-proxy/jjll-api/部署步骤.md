## 一、开通 OSS 并建 Bucket

1. 登录 [阿里云控制台](https://oss.console.aliyun.com) → 左侧「Bucket 列表」→ **创建 Bucket**
2. 填写：
   - Bucket 名称：`jijilili`（全局唯一，被占用就换 `jijilili-family` 之类）
   - 地域：**华东1（杭州）** ← 必须和你的 FC 同地域，才能走内网免流量
   - 存储类型：标准存储
   - 读写权限：**公共读**（照片要让 `<img>` 直接显示；写入仍要经过 FC 签名，别人写不了）
   - 其余默认 → 确定
3. 记下**外网访问域名**：`https://jijilili.oss-cn-hangzhou.aliyuncs.com`
   （Bucket 概览页最下方「访问域名」→「外网访问」）

### 配置 CORS（否则浏览器无法抓取原图生成缩略图）

Bucket 左侧菜单「数据安全」→「跨域设置」→「创建规则」：
- 来源：`*` （想更安全就填 `https://assassinxxl.github.io`）
- 允许 Methods：勾选 `GET`、`POST`、`PUT`、`HEAD`
- 允许 Headers：`*`
- 暴露 Headers：`ETag`、`Content-Length`
- 缓存时间：600

## 二、建一个只管这个 Bucket 的 RAM 子账号（推荐，避免主账号密钥泄露）

1. 控制台右上角头像 → **访问控制 RAM** → 「身份管理 → 用户」→ **创建用户**

   - （更严格可自定义策略只授权这一个 bucket，先用这个即可）

> 🆘 **如果你已经建了「自定义运行时」且一直起不来**
> （Invalid zip file → CAFileNotFound → CAFilePermission → 改启动命令后**彻底无法访问**）：
> 别再在自定义运行时上修了，**删掉重建为「Web 函数」**。这是最根本的解法，能同时避开
> bootstrap 缺失、bootstrap 无执行权限、找不到启动命令、监听端口不匹配这一连串坑。
>
> - Web 函数**不需要 bootstrap、也不需要手动配启动命令**——FC 用内置 Node Web 运行时自动拉起
>   你的 `index.js`（监听 `PORT` 环境变量，代码已兼容），你只要上传 `jjll-api.zip`、配置好后端
>   参数、建一个 HTTP 触发器（无需认证）即可。
> - 「彻底无法访问」的本质是**函数实例起不来**（FC 健康检查连不上）。几乎都是因为：代码包一直
>   没部署成功（之前 Invalid zip file 被拒收过，函数里其实没代码），或启动命令 / 监听端口填错。
>   换 Web 函数从根上消除这两类问题。
> - 想**不再折腾「环境变量」入口**？见下面第 3 步的「代码内置配置」退路：直接把 6 个值填进
>   `index.js` 顶部的 `DEFAULTS`，连环境变量都不用配，部署即生效。
>
> 下面第 2 步就是 Web 函数的标准建法，照做即可。

## 三、创建函数计算的后端函数

1. 打开 [函数计算控制台](https://fcnext.console.aliyun.com) → 地域选 **华东1（杭州）**
2. 「函数」→ **创建函数** → 选 **Web 函数**
   - 函数名称：`jjll-api`
   - 运行环境：**Node.js 18** 或 Node.js 20
   - **代码上传**：选「上传代码包」，用我给你的 **`jjll-api.zip`**（里面只有根目录 `index.js`，
     结构一定正确；别自己压文件夹，否则会变成 `jjll-api/index.js` 嵌套导致 Invalid zip file）
   - Web 函数**不需要**配启动命令和监听端口（FC 自动注入 `PORT=9000`，代码已兼容），这两项保持默认即可

   > ⚠️ **千万不要选「自定义运行时 / Custom Runtime」！** 本项目代码是一个独立 Node HTTP 服务
   > （自己 `server.listen`），只适配 **Web 函数**。若误选自定义运行时，调用会依次报
   > `CAFileNotFound ... /code/bootstrap is not exist` → `CAFilePermission ... bootstrap file don't have
   > execute permissions`——因为自定义运行时**默认启动命令是 `/code/bootstrap` 且必须可执行**，而
   > Windows 打的 zip 解压后**不保留可执行权限位**，反复踩坑。
   >
   > **已误选自定义运行时的救法（不用重建函数，最省事）**：把启动命令改成 `node /code/index.js`，
   > FC 检测到你配了启动命令就**不再执行 bootstrap**，权限报错当场消失：
   > 1. 函数详情 → **「配置」** 页签
   > 2. 找「启动命令」的入口（**它不在「高级配置」里**）：
   >    - **首选**：点「配置」页**右上角的「编辑」**（整个配置页的总编辑按钮，不是某个小分块的编辑）
   >      → 弹出的面板里**往下翻**就能看到「启动命令」和「监听端口」，和环境变量不在同一块；
   >    - 或逐块找：在 **「基础配置」/「基础信息」** 那一块点它的「编辑」，启动命令就在那里。
   > 3. 在面板里找到 **「启动命令」** → 填 `node /code/index.js`
   >    （有的版本拆成"命令/参数"两格：命令填 `node`，参数填 `/code/index.js`）
   > 4. 确认 **「监听端口」** 是 **9000**（代码已监听 `0.0.0.0:9000`，与自定义运行时默认端口一致）
   > 5. 面板底部点 **「部署」**
   >
   > 然后「代码」页上传 `jjll-api.zip`（只有根目录 `index.js`）再点部署即可。
   > 此修法**完全不动**你已配的环境变量和触发器。
   >
   > **如果实在找不到「启动命令」这一项**：最干净的办法是**重建函数为「Web 函数」**（见下方说明），
   > Web 函数不需要 bootstrap、也不需要启动命令，从根本上避开这条坑。
3. 配置环境变量。这一步的入口藏得比较深，按下面顺序点：

   1. 左侧菜单 **「函数」** → 点函数名 `jjll-api` 进入**函数详情**
   2. 详情页顶部有一排页签：**代码 / 配置 / 触发器 / 版本 / 别名…** → 点 **「配置」**
   3. 往下翻，找到 **「高级配置」** 这一块 → 点它**右上角的「编辑」**
      （注意：不要点「基础信息」那块的编辑，环境变量不在这里）
   4. 弹出「高级配置」面板 → 里面找到 **「环境变量」** → 点 **「+ 添加变量」**，
      逐条填 `变量` 和 `值`（每填一条再点一次「+ 添加变量」）
   5. **省事做法**：面板里有个 **「使用 JSON 格式编辑」**，切过去后一次性粘贴下面这段
      （把值换成你自己的），省得填 6 次：

      ```json
      {
        "OSS_AK": "你的AccessKeyId",
        "OSS_SK": "你的AccessKeySecret",
        "OSS_BUCKET": "jijilili",
        "OSS_ENDPOINT": "oss-cn-hangzhou-internal.aliyuncs.com",
        "OSS_PUBLIC_BASE": "https://jijilili.oss-cn-hangzhou.aliyuncs.com",
        "JJLL_TOKEN": "jjll-2026"
      }
      ```

   6. 面板底部点 **「部署」**（不改代码也要点一下，配置才会生效）

   | 变量名 | 值 | 说明 |
   |---|---|---|
   | `OSS_AK` | 上一步的 AccessKey ID | RAM 子账号的 |
   | `OSS_SK` | 上一步的 AccessKey Secret | |
   | `OSS_BUCKET` | `jijilili`（你的 bucket 名） | |
   | `OSS_ENDPOINT` | `oss-cn-hangzhou-internal.aliyuncs.com` | **内网**域名，与杭州 FC 互通免流量费 |
   | `OSS_PUBLIC_BASE` | `https://jijilili.oss-cn-hangzhou.aliyuncs.com` | Bucket 的外网访问域名 |
   | `JJLL_TOKEN` | 自己起一个口令，如 `jjll-2026` | 可选，但建议设 |

   > **实在找不到这个入口，还有个退路**：直接编辑 `jjll-api/index.js` 文件顶部第 36 行起的
   > `DEFAULTS = { ... }`，把 6 个值填在引号里，保存后点「部署」即可，效果完全一样。
   > 两种方式是「或」的关系，环境变量优先。

4. 「触发器」→ **创建触发器**
   - 触发器类型：HTTP 触发器
   - 请求方法：勾选 `GET`、`POST`、`OPTIONS`
   - 认证方式：**无需认证**（anonymous）
5. 复制「函数 URL」，形如：
   `https://jjll-api-xxxxx.cn-hangzhou.fcapp.run`

> **⚠️ 关于触发器与「另一个函数」的避坑（新手常踩）**
> - **一个函数只能有一个 HTTP 触发器**。创建函数时系统已经自动建了一个（就是你看到的那个），
>   所以"再创建触发器"会提示"只能创一个"——这是正常的，不用再建，**直接编辑现有触发器**
>   把「认证方式」改成「无需认证」即可。
> - 触发器若是「签名认证」，浏览器 `fetch` 直接调会报
>   `MissingRequiredHeader: required HTTP header Date was not specified`——因为前端不做阿里云签名。
>   改成「无需认证」后这个错就消失；若随后变成 `Invalid zip file`，说明代码包从未部署成功
>   （压缩包不合格被拒收），按上面「代码 / 上传代码包」把 `jjll-api.zip` 传上去并点「部署」即可。
> - **重新上传代码 / 改代码只影响当前这一个函数，不会动到别的任何函数**（函数之间完全隔离）。
>   若之前手滑建了两个函数，互相也不影响；建议把没用到的空函数删掉，免得弄混。
> - 若报 `CAFilePermission ... permission denied ... /code/bootstrap`：这是 bootstrap 没可执行权限。
>   **不要去折腾 bootstrap 文件权限**（Windows 打 zip 解压后权限位会被丢），直接按上面「已误选自定义运行时的救法」
>   把启动命令改成 `node /code/index.js` 并部署，FC 就不再读 bootstrap，报错消失。

### 验证

浏览器直接打开这个函数 URL，应返回 JSON：

```json
{ "ok": true, "service": "jijilili-backend", "bucket": "jijilili",
  "publicBase": "https://jijilili.oss-cn-hangzhou.aliyuncs.com",
  "oss": "OK（OSS 可读写）" }
```

返回里还有一个 `config` 字段，会逐条告诉你每个值是从哪儿读到的，排查时很有用：

```json
"config": { "OSS_AK": "环境变量", "OSS_SK": "环境变量",
            "OSS_BUCKET": "❌ 缺失", ... }
```

- 出现 **`❌ 缺失`**：环境变量没配上（或没点「部署」）→ 补齐后重新部署
- 出现 **`"oss": "FAIL..."`** 或 HTTP 403：AK/SK 或 bucket 名填错，或子账号没给 OSS 权限
- 出现 **`环境变量` / `代码内置`**：说明值已经读到，问题在 AK/SK 权限或 bucket 名

## 三·补、把老照片从 Supabase 搬到 OSS（两种办法，选一个）

### 办法 A：网页端一键迁移（推荐，前提是当前网络能连上 Supabase）

1. 先确认网络能打开 Supabase：浏览器访问
   `https://lrjiiacbzpcfpstxakuu.supabase.co/rest/v1/families?select=code&limit=1`
   能返回 JSON 就说明通。
2. 网页 `⚙️ 接口与存储设置` → 填好国内云地址并保存 → 点 **🚚 迁移照片到国内云**
3. 它按这个顺序取图，**优先保原图画质**：
   本机 IndexedDB 原图副本 → **趁网络通直接从原地址拉原图** → 图片代理 → 缩略图（降级）
4. 结果会显示 `成功 x 张（其中 n 张只有缩略图，画质较低），失败 m 张`。
   - 出现"失败"多半是浏览器跨域被拦（Supabase 没给 CORS 头）→ 改用办法 B
   - 出现"降级"说明本机和原地址都拿不到原图，只剩缩略图可用

> 小技巧：点迁移前，先在日历里把有照片的日期都翻一遍，让照片加载一次，
> 程序会自动在本机留一份原图副本，迁移时就能直接用（不依赖跨域）。

### 办法 B：命令行迁移（不受跨域限制，画质无损）

浏览器抓不到原图时用这个。脚本在 `tools/migrate-to-oss.js`：

1. 网页端「设置 → 数据管理 → 导出数据」→ 得到 `jijilili-data.json`
2. 在 PowerShell 里执行（注意用外网 endpoint，从你电脑上传）：

   ```powershell
   cd C:\Users\11637\WorkBuddy\20260504223628\jijilili-app
   $env:OSS_AK="你的AccessKeyId"
   $env:OSS_SK="你的AccessKeySecret"
   $env:OSS_BUCKET="jijilili"
   $env:OSS_ENDPOINT="oss-cn-hangzhou.aliyuncs.com"
   $env:OSS_PUBLIC_BASE="https://jijilili.oss-cn-hangzhou.aliyuncs.com"
   node tools/migrate-to-oss.js jijilili-data.json
   ```

3. 脚本会逐个下载原图 → 上传到 `photos/migrated/` → 生成 `jijilili-data-oss.json`
4. 网页端「设置 → 数据管理 → 导入数据」选这个新文件即可
