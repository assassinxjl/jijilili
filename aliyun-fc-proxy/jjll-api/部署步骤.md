## 一、开通 OSS 并建 Bucket

1. 登录 [阿里云控制台](https://oss.console.aliyun.com) → 左侧「Bucket 列表」→ **创建 Bucket**
2. 填写：
   - Bucket 名称：`jijilili`（全局唯一，被占用就换 `jijilili-family` 之类）
   - 地域：**华东1（杭州）** ← 必须和你的 FC 同地域，才能走内网免流量
   - 存储类型：标准存储
   - 读写权限：**公共读**（照片要让 `<img>` 直接显示；写入仍要经过 FC 签名，别人写不了）
   - 其余默认 → 确定
3. 记下**外网访问域名**：`https://jijilili.oss-cn-hangzhou.aliyuncs.com`
   （Bucket 概览页最下方「访问域名」→「外网访问」）

### 配置 CORS（否则浏览器无法抓取原图生成缩略图）

Bucket 左侧菜单「数据安全」→「跨域设置」→「创建规则」：
- 来源：`*` （想更安全就填 `https://assassinxxl.github.io`）
- 允许 Methods：勾选 `GET`、`POST`、`PUT`、`HEAD`
- 允许 Headers：`*`
- 暴露 Headers：`ETag`、`Content-Length`
- 缓存时间：600

## 二、建一个只管这个 Bucket 的 RAM 子账号（推荐，避免主账号密钥泄露）

1. 控制台右上角头像 → **访问控制 RAM** → 「身份管理 → 用户」→ **创建用户**
   - 登录名称：`jjll-app`，访问方式：勾选 **「使用永久 AccessKey 访问」**
   - 创建后**立刻复制保存 AccessKey ID 和 Secret**（关掉就再也看不到 Secret）
2. 回到用户列表 → 点该用户 → 「权限管理 → 新增授权」
   - 权限策略：搜索并添加 `AliyunOSSFullAccess`
   - （更严格可自定义策略只授权这一个 bucket，先用这个即可）

## 三、创建函数计算的后端函数

1. 打开 [函数计算控制台](https://fcnext.console.aliyun.com) → 地域选 **华东1（杭州）**
2. 「函数」→ **创建函数** → 选 **Web 函数**
   - 函数名称：`jjll-api`
   - 运行环境：**Node.js 18** 或 Node.js 20
   - 代码上传：选「上传代码包 / 文件夹」，把 `jjll-api/index.js` 上传（入口文件需叫 `index.js`）
   - 启动命令、监听端口保持默认（Web 函数默认监听 9000，代码里已兼容 `CAPORT`）
3. 创建完成后 → 函数详情 → 「配置」→ **环境变量** → 编辑 → 新增：

   | 变量名 | 值 |
   |---|---|
   | `OSS_AK` | 上一步的 AccessKey ID |
   | `OSS_SK` | 上一步的 AccessKey Secret |
   | `OSS_BUCKET` | `jijilili`（你的 bucket 名） |
   | `OSS_ENDPOINT` | `oss-cn-hangzhou-internal.aliyuncs.com`（**内网**域名，与杭州 FC 互通免流量费） |
   | `OSS_PUBLIC_BASE` | `https://jijilili.oss-cn-hangzhou.aliyuncs.com`（Bucket 的外网访问域名） |
   | `JJLL_TOKEN` | 自己起一个口令，如 `jjll-2026`（可选，但建议设） |

4. 「触发器」→ **创建触发器**
   - 触发器类型：HTTP 触发器
   - 请求方法：勾选 `GET`、`POST`、`OPTIONS`
   - 认证方式：**无需认证**（anonymous）
5. 复制「函数 URL」，形如：
   `https://jjll-api-xxxxx.cn-hangzhou.fcapp.run`

### 验证

浏览器直接打开这个函数 URL，应返回 JSON：

```json
{ "ok": true, "service": "jijilili-backend", "bucket": "jijilili",
  "publicBase": "https://jijilili.oss-cn-hangzhou.aliyuncs.com",
  "oss": "OK（OSS 可读写）" }
```

如果 `"oss": "FAIL..."` 或显示 HTTP 403，说明 AK/SK 或 bucket 名填错，按提示改环境变量即可。

## 三·补、把老照片从 Supabase 搬到 OSS（两种办法，选一个）

### 办法 A：网页端一键迁移（推荐，前提是当前网络能连上 Supabase）

1. 先确认网络能打开 Supabase：浏览器访问
   `https://lrjiiacbzpcfpstxakuu.supabase.co/rest/v1/families?select=code&limit=1`
   能返回 JSON 就说明通。
2. 网页 `⚙️ 接口与存储设置` → 填好国内云地址并保存 → 点 **🚚 迁移照片到国内云**
3. 它按这个顺序取图，**优先保原图画质**：
   本机 IndexedDB 原图副本 → **趁网络通直接从原地址拉原图** → 图片代理 → 缩略图（降级）
4. 结果会显示 `成功 x 张（其中 n 张只有缩略图，画质较低），失败 m 张`。
   - 出现"失败"多半是浏览器跨域被拦（Supabase 没给 CORS 头）→ 改用办法 B
   - 出现"降级"说明本机和原地址都拿不到原图，只剩缩略图可用

> 小技巧：点迁移前，先在日历里把有照片的日期都翻一遍，让照片加载一次，
> 程序会自动在本机留一份原图副本，迁移时就能直接用（不依赖跨域）。

### 办法 B：命令行迁移（不受跨域限制，画质无损）

浏览器抓不到原图时用这个。脚本在 `tools/migrate-to-oss.js`：

1. 网页端「设置 → 数据管理 → 导出数据」→ 得到 `jijilili-data.json`
2. 在 PowerShell 里执行（注意用外网 endpoint，从你电脑上传）：

   ```powershell
   cd C:\Users\11637\WorkBuddy\20260504223628\jijilili-app
   $env:OSS_AK="你的AccessKeyId"
   $env:OSS_SK="你的AccessKeySecret"
   $env:OSS_BUCKET="jijilili"
   $env:OSS_ENDPOINT="oss-cn-hangzhou.aliyuncs.com"
   $env:OSS_PUBLIC_BASE="https://jijilili.oss-cn-hangzhou.aliyuncs.com"
   node tools/migrate-to-oss.js jijilili-data.json
   ```

3. 脚本会逐个下载原图 → 上传到 `photos/migrated/` → 生成 `jijilili-data-oss.json`
4. 网页端「设置 → 数据管理 → 导入数据」选这个新文件即可

## 四、前端配置（网页版）

1. 先把代码推到 GitHub（命令行需要你的凭据，我这边没有）：

   ```bash
   cd C:/Users/11637/WorkBuddy/20260504223628/jijilili-app
   git push origin main
   ```

2. 手机和电脑都打开网页 → `⚙️ 接口与存储设置`
   - **国内云 API 地址**：填上面的函数 URL
   - **访问口令**：填 `JJLL_TOKEN` 的值（没设就留空）
   - 保存

   这个地址会随家庭数据同步，**填一次所有设备自动生效**。

3. 点 **🚚 迁移照片到国内云**
   - 它会把照片从 Supabase（现在连不上）换成本地已有的原图副本 / IndexedDB / 缩略图上传到 OSS
   - 显示 `迁移完成：成功 x 张` 后，照片引用就全部指向国内了

4. 之后新拍的照片会直接上传到 OSS，任何网络都能显示。
